# Baby Milestones

Design decisions live in docs/design-document.md. Read it before changing architecture.

- TDD: failing test first, make it pass, then refactor.
- SOLID and clean code; small, well-named classes and methods.
- Comments only where something genuinely needs explaining.
- `core` is pure Kotlin (kotlinx.serialization only): no Android, Spring or vendor types. App and server must agree,
  so any rule about ages, statuses, concerns or schedules goes in `core`, never in one of them.
- Content is data in `core/src/main/resources/content/`, never hard-coded or generated by a model. Every milestone,
  period and schedule entry cites references; `ContentValidator` and `ContentBundleTest` must pass. Bump
  `manifest.json`'s version when content changes.
- Never add diagnosis, condition names, screening scores or medicine advice to content, prompts or tool results.
- Secrets come from environment variables; never commit .env.
- Build with JDK 21: `export JAVA_HOME=~/.sdkman/candidates/java/21.0.12+1.1-tem`, then
  `./gradlew :core:test :server:test :app:testDebugUnitTest :app:assembleDebug` (server tests need Docker).
